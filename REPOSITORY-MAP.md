## Organization rules

1. Keep original projects separate from upstream mirrors, forks, and learning references.
2. Do not place private repository names, backup contents, credentials, or customer data in this public index.
3. Do not delete, archive, rename, or merge repositories as part of routine organization.
4. Before moving files, inspect the complete tree and update every path/reference in the same change.
5. Keep one canonical live portfolio and separate client websites from the personal portfolio.
6. Add a clear README, purpose, setup instructions, license status, and maintenance notes to each actively maintained original project.

## Audit notes

- Empty repositories need a purpose decision before source files are added.
- `PortfolioDraco10101` is currently a secondary/legacy portfolio placeholder; `Draco-Website` is the active published portfolio.
- Repositories that mirror upstream projects should retain upstream attribution, original license files, and source history.
